# info - модуль сбора системной информации Windows

> [English version](README.md)

**info** - лёгкий C-модуль, который собирает информацию о железе и программном обеспечении под Windows **исключительно через Windows API и реестр Windows**. Модуль не использует WMI, WMIC, OLE и COM в какой-либо форме.

В репозитории также находится **test_info** - небольшое консольное демо-приложение, которое линкует модуль и выводит собранные данные. Демо вторично: модуль является основным результатом и может использоваться в любом C/C++ проекте.

## Описание

Модуль предоставляет плоский data-oriented API: каждая функция заполняет буфер или структуру, переданную вызывающим кодом, и возвращает количество элементов или статус. Нет глобальных переменных, нет внутренних аллокаций, живущих дольше вызова, нет потоков и нет последовательности инициализации/завершения - функцию можно вызвать в любой момент, и повторные вызовы безопасны.

Цель проекта - собрать как можно больше системной информации без использования стека Windows Management Instrumentation. Все данные читаются прямыми вызовами Win32 API и запросами к реестру, что делает модуль быстрым, свободным от зависимостей и простым для аудита. Все wide-строки транскодируются во внутреннем представлении в UTF-8, поэтому потребитель работает с обычными `char`-буферами.

Исходники не зависят от конкретного компилятора в рамках тулчейна MinGW-w64: одни и те же файлы собираются как C через `gcc` и как C++ через `g++` без каких-либо изменений (публичный заголовок обёрнут в `extern "C"`).

## Возможности

Модуль умеет собирать:

- **CPU** - модель, вендор, архитектура (x86/x64/ARM/ARM64/Itanium), базовая частота, количество логических/физических ядер, количество пакетов
- **Материнская плата** - производитель платы, модель платы, производитель/модель системы, вендор и версия BIOS
- **Память** - общий и доступный объём физической RAM
- **ОС** - имя ядра, полное имя продукта, major/minor версия, номер сборки, UBR
- **Диски** - буквы дисков, тип, файловая система, метка тома, серийный номер тома
- **GPU** - активные видеоадаптеры с именами дочерних устройств
- **HID** - количество подключённых мышей, клавиатур и других HID-устройств
- **Сеть** - список установленных сетевых адаптеров
- **Дисплеи** - разрешение, DPI, глубина цвета, частота обновления для каждого монитора
- **Время** - локальная дата/время и смещение часового пояса
- **Язык** - языки активных раскладок клавиатуры
- **Экран** - размер виртуального экрана
- **Процессы** - запущенные процессы в `C:\Windows` (PID + путь к образу)
- **Модули** - модули процесса в `C:\Windows`
- **Драйверы** - загруженные ядра драйверов в `system32`
- **Программы** - установленное ПО (записи Microsoft Corporation пропускаются)
- **Службы** - активные службы с бинарником в `C:\Windows`

## Технологии

- **Язык:**; исходники являются валидным C++ и собираются без изменений через `g++`
- **Компилятор:** MinGW-w64 `gcc` / `g++` (x86_64)
- **Платформа:** Windows 10 / 11, x64
- **API:** Win32 API, реестр Windows, SetupAPI, PSAPI, Toolhelp32
- **Зависимости:** отсутствуют - только системные DLL, без сторонних библиотек
- **Кодировка вывода:** UTF-8 (все wide-строки транскодируются через `WideCharToMultiByte`)

Фильтрация по системным путям сужает вывод до самой ОС и снижает шум от пользовательских приложений.

## Демо-приложение: test_info

**test_info** - консольное демо, которое линкует модуль и выводит все секции, которые тот умеет собирать. Оно существует для демонстрации API модуля и служит образцом вызовов; оно не является частью самого модуля.

### Сборка

```bat
build_info.bat:: сборка демо как C через gcc
build_info.bat cpp:: сборка демо как C++ через g++
```

Оба варианта создают `test_info.exe` в каталоге проекта.

### Запуск

```bat
test_info.exe
```

Демо выводит следующие секции в порядке:

1. OS
2. CPU
3. Quantities
4. Motherboard
5. Memory
6. Disk
7. GPU
8. Connected HIDs
9. Network
10. Displays
11. Time Date
12. Language
13. Screen
14. Process
15. Modules
16. Drivers
17. Softwares
18. Services

### Примечания

- Права администратора не требуются; защищённые системные процессы просто пропускаются.
- Демо не выполняет сетевых операций и не собирает телеметрию.
- Результат - один самодостаточный исполняемый файл без зависимостей, кроме системных DLL Windows.
